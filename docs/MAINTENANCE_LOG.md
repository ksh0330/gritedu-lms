## Purpose and maintenance rules

This is the canonical, append-only record for material code, Firestore Rules, Functions, schema, deployment, retention, and operational behavior changes.

- Add one compact entry at the end for each material task or deployment. Do not delete or reorder historical entries.
- Use only these statuses: `Open`, `In progress`, `Implemented`, `Deployed`, `Verified`, `Closed`, `Deferred`.
- `Implemented` means the repository change and local checks are complete. `Deployed` means the approved production deployment completed. `Verified` additionally requires the documented production checks.
- A status transition is the only normal in-place change to an entry. Add a dated owner-verification note whenever the status changes.
- Append corrections instead of rewriting historical facts.
- Do not duplicate large audit tables. Link to the relevant canonical document.
- Never record secrets, personal data, OTP values, emails, phone numbers, private URLs, or production document contents.
- Trivial formatting-only changes do not require an entry.
